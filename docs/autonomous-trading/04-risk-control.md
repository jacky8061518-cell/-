# 04 風險控制

## 0. 核心立場

**風控不是策略的一部分，是策略的上級。** 策略只能提出請求，風控決定通不通過。
兩者的程式碼、設定、部署、變更審核全部分離。任何讓策略能夠修改自身限額的
設計，都是把煞車踏板接到油門上。

## 1. 三層防線

```text
┌─ 第一層：訊號層 ──────────────────────────────────────────┐
│ 在訊號產生時就內建風險意識                                  │
│ · 信心分數低於門檻直接不發                                  │
│ · 資料品質 stale / 來源衝突 → 降級或不發                    │
│ · 波動率調整後的預期報酬 / 預期風險 < 門檻 → 不發            │
└──────────────────────────────────────────────────────────┘
┌─ 第二層：組合層 ──────────────────────────────────────────┐
│ 在下單前檢查對整體組合的影響                                │
│ · 單一標的、單一產業、單一因子的曝險上限                     │
│ · 相關性叢集限制（見 §3）                                   │
│ · 總槓桿、淨曝險、毛曝險上限                                │
│ · 流動性限制：不超過 ADV 的 x%                              │
└──────────────────────────────────────────────────────────┘
┌─ 第三層：帳戶層（熔斷） ──────────────────────────────────┐
│ 不管訊號多好，觸發就停                                      │
│ · 日內虧損、週虧損、月虧損上限                              │
│ · 回撤達門檻自動縮減部位                                    │
│ · 異常行為偵測（下單頻率暴增、拒單率飆高）                   │
│ · Kill switch（人工 + 自動）                               │
└──────────────────────────────────────────────────────────┘
```

## 2. 部位大小：從信心到金額

不要固定張數，也不要 all-in。用**波動率目標 × 信心縮放**：

```text
基礎部位     w_base = (目標波動率 / 標的年化波動率) × 基準權重
信心縮放     w = w_base × f(p)     p 為 meta-model 的執行機率
             f(p) = clip(2p - 1, 0, 1)     p<0.5 不進場；p=0.75 → 半倉
凱利上限     w ≤ 0.25 × Kelly     （分數凱利；全凱利在估計誤差下必爆）
硬上限       w ≤ 單一標的上限（例如 5%）
最終         w_final = min(以上所有)
```

三個實務要點：

- **波動率目標化讓不同標的可比**：買 10% 的低波股與 10% 的高波股，風險差 3 倍。
  用波動率調整後，「權重」才真的等於「風險預算」。
- **分數凱利**：全凱利假設你知道真實勝率。你不知道。用 1/4 凱利。
- **最小交易金額**：小於成本效益門檻的部位不下單，避免被手續費凌遲。

## 3. 相關性風險（最容易被忽略的殺手）

「我分散在 20 檔股票」在 2020 年 3 月毫無意義——它們一起跌。做法：

1. 每日計算持倉的相關矩陣（用 EWMA，λ=0.94），做階層式分群
2. **限制的是「叢集」而非「標的」**：任一相關性叢集的曝險 ≤ 20%
3. 計算 **有效持倉數** `N_eff = 1 / Σw_i²`（考慮相關性後的分散化參與度），
   低於門檻就告警
4. **壓力期相關性收斂**：用危機期間（2008、2020、2022）的相關矩陣再算一次
   組合風險，這才是真實的下檔曝險

## 4. 熔斷矩陣

| 觸發條件 | 動作 | 恢復方式 |
| --- | --- | --- |
| 日內虧損 > 2% NAV | 停止新進場，既有部位保留 | 隔日自動 |
| 日內虧損 > 4% NAV | 平倉至 50%，停止交易 | 人工核准 |
| 滾動 5 日虧損 > 6% | 全系統暫停 | 人工覆盤後 |
| 回撤 > 10% | 部位規模全面 ×0.5 | 回撤修復至 5% 內自動恢復 |
| 回撤 > 20% | 全平倉，系統下線 | 人工重新驗證全流程 |
| 單一訊號連續 5 次錯誤 | 該模型停用 | Post-mortem Agent 覆盤後 |
| 行情延遲 > 3 秒 | 只出不進 | 延遲恢復後自動 |
| 券商拒單率 > 20% | 停止下單 | 人工 |
| 特徵分佈 PSI > 0.25 | 該模型信心分數 ×0.5 並告警 | 再訓練後 |
| LLM 降級為規則式 | 依賴語意特徵的訊號不發 | API 恢復後 |

**恢復必須比觸發困難。** 自動觸發、人工恢復是預設；只有明確可逆的技術性
狀況（延遲、回撤修復）才允許自動恢復。

## 5. Kill Switch 的具體要求

- **物理上獨立**：一個不依賴主系統的端點，主系統掛掉時它仍要能用
- **三秒內生效**：撤掉所有掛單、停止所有 Agent 的下單權限
- **兩種模式**：`halt`（停止新單，保留部位）與 `flatten`（全部平掉）
- **每月演練一次**，並記錄實際生效時間。沒演練過的 kill switch 等於沒有
- **權限**：交易員與風控主管都能按；重新啟用需要兩人核准

## 6. 執行風險

自動化系統最貴的錯誤往往發生在下單環節：

| 風險 | 防護 |
| --- | --- |
| 重複下單 | 訂單冪等鍵 = hash(decision_id, symbol, side, target_qty)；重送不重複 |
| 肥手指 | 下單前檢查：數量 vs 平均下單量、金額 vs NAV、價格 vs 現價偏離 |
| 追價無限 | 限價單 + 最大滑價容忍；超過就撤單重評估，不用市價單追 |
| 部分成交 | 明確的部分成交處理邏輯；未成交部分的有效期限 |
| 對帳不符 | 每筆交易都有紀錄可對帳，券商部位 vs 系統部位每小時比對，不符即告警 |
| 系統重啟後狀態遺失 | 部位狀態以券商回報為準（single source of truth），啟動時強制對帳 |

**啟動時的第一件事永遠是對帳，不是交易。** 系統重啟後在完成部位對帳前，
禁止產生任何訂單。

## 7. 上線檢查表

真錢之前，以下每一項都要打勾：

- [ ] walk-forward 樣本外至少 24 個月，交易次數 > 200
- [ ] Deflated Sharpe Ratio > 0，且扣 3 倍成本後仍為正
- [ ] 訊號延遲 1 根 K 棒後，績效衰減 < 50%
- [ ] 隨機標籤測試回到隨機水準（證明沒有資料洩漏）
- [ ] paper trading ≥ 60 個交易日，且實際 vs 理論的追蹤誤差 < 20%
- [ ] 所有熔斷條件都在測試環境**實際觸發過一次**（不是只寫在程式碼裡）
- [ ] kill switch 演練通過，實測生效時間有紀錄
- [ ] 對帳流程跑過完整一週無誤
- [ ] 每個外部依賴的斷線降級行為都測試過
- [ ] 模型退場條件已寫入設定並啟用
- [ ] 有明確的人為監督責任人與升級路徑

## 8. 給交易員的風險儀表板

即時顯示，不要藏在報表裡：

- 當前風險預算使用率（已用 / 上限）
- 各叢集曝險與有效持倉數
- 今日 P&L 與距離熔斷門檻的距離（用進度條，一眼看到）
- 各模型的滾動表現與健康狀態燈號
- 資料品質燈號：每個來源的最後更新時間與延遲
- 待處理的降級事件與告警
