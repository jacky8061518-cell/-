# 05 情報產出：交易員實際看到什麼

## 0. 設計前提

交易員的稀缺資源是**注意力**，不是資訊。系統的價值不在於「掃描了 5000 檔股票」，
而在於「今天只給你 4 條需要決定的事」。

**訊號預算**：每日 confirmed signal 上限（例如 10 條）。超過就代表門檻太鬆，
系統應自動提高信心門檻，而不是照發。寧可漏，不可洗版——被洗版的告警系統，
第二週就會被交易員關掉。

## 1. 訊號卡（Signal Card）

每條訊號必須包含以下欄位，缺一不發：

```json
{
  "signal_id": "sig_20260908_2330TW_001",
  "decision_id": "dec_...",
  "created_at": "2026-09-08T01:32:11Z",
  "symbol": "2330.TW",
  "direction": "long",
  "conviction": 0.72,
  "horizon": "5-10 個交易日",

  "thesis": "外資連 3 日買超創 20 日新高，同時 AI 伺服器供應鏈上修財測；\n價格尚未反映，距 20 日均線僅 +1.2%",

  "evidence": [
    {"type": "flow",      "detail": "外資買超 z=2.8（20日）", "weight": 0.35, "source_event_id": "evt_..."},
    {"type": "news",      "detail": "客戶上修 2026 CapEx 指引", "weight": 0.30, "source_event_id": "evt_..."},
    {"type": "momentum",  "detail": "相對大盤 RS 進入領先象限", "weight": 0.20, "source_event_id": "evt_..."},
    {"type": "sentiment", "detail": "分析師調升廣度 0.6 → 0.8", "weight": 0.15, "source_event_id": "evt_..."}
  ],

  "counter_evidence": [
    {"detail": "選擇權偏斜偏空，法人可能在避險", "severity": "medium"},
    {"detail": "本週五除息，短線可能有賣壓", "severity": "low"}
  ],

  "regime_context": "低波動 / risk-on / 半導體處於 RRG 領先象限",

  "risk": {
    "suggested_weight_pct": 3.2,
    "stop_level": 1042.0,
    "stop_basis": "2×ATR(14)",
    "max_loss_pct_nav": 0.48,
    "target_level": 1180.0,
    "reward_risk": 2.1
  },

  "invalidation": "外資轉為連 2 日賣超，或跌破 1042",

  "data_quality": {"all_sources_fresh": true, "stale_sources": [], "conflicts": []},

  "model_provenance": {
    "models": ["momentum_v3", "flow_v2", "meta_label_v4"],
    "feature_set_version": "fs_2026_08",
    "replay_command": "replay --decision-id dec_..."
  }
}
```

三個必要欄位常被忽略但最有價值：

- **`counter_evidence`（反面證據）**：只講多頭理由的系統，交易員三週後就不信了。
  主動呈現反證是建立信任的關鍵，也逼系統誠實。
- **`invalidation`（失效條件）**：告訴交易員「什麼情況下這條訊號就錯了」。
  沒有失效條件的訊號無法管理。
- **`replay_command`**：交易員能自己回溯，不必問工程師。

## 2. 警示分級

| 級別 | 定義 | 通道 | 預期頻率 |
| --- | --- | --- | --- |
| **P0 危機** | 熔斷觸發、系統故障、部位對帳不符、kill switch | 電話 + 推播 + 桌面彈窗 | 極罕見 |
| **P1 行動** | 高信心訊號、既有部位的失效條件觸發、停損逼近 | 推播 + 桌面 | 每日 0~5 |
| **P2 注意** | 中信心訊號、regime 切換、重大新聞影響持倉 | 桌面通知 | 每日 5~15 |
| **P3 情報** | 敘事更新、統計異常、觀察名單變化 | 面板內，不主動打擾 | 持續 |
| **P4 日誌** | 一切其他 | 只進日誌，可查詢 | — |

**分級的紀律**：每週檢視「P1 告警中，交易員實際採取行動的比例」。
低於 50% 代表 P1 定義太鬆，必須調緊。這個比例是系統健康的核心 KPI。

## 3. 每日簡報（Daily Brief）

三個時點自動產生，每份 **一頁以內**：

### 盤前（開盤前 60 分鐘）
1. 隔夜發生什麼（3 條，含對持倉的具體影響）
2. 今日 regime 判定與變化
3. 今日觀察清單（含觸發條件，不是清單而已）
4. 需要注意的事件（財報、經濟數據、除權息、解禁）
5. 現有部位的健康度與失效條件距離

### 盤中（每 2 小時或重大事件）
- 只在有實質變化時發，沒事就不發

### 盤後
1. 今日 P&L 歸因（哪個模型、哪個因子貢獻多少）
2. 今日訊號的即時評估
3. 錯誤與意外（含系統層面）
4. 明日待辦與觀察

## 4. 交易員操作介面

呼應檢核清單階段 2（前端體驗），實際需要的元件：

| 元件 | 用途 | 關鍵設計 |
| --- | --- | --- |
| **訊號流** | 主畫面，時間序的訊號卡 | 可依信心／產業／模型篩選；一鍵展開證據鏈 |
| **持倉監控** | 現有部位 + 每個部位的失效條件距離 | 進度條顯示距停損／目標的距離 |
| **風險面板** | [04](04-risk-control.md) §8 的內容 | 一眼看到距離熔斷多遠 |
| **敘事地圖** | 今日市場主軸與受影響標的 | 熱力圖或聚類視圖 |
| **研究工作台** | 交易員自己提問、跑回測 | 現有 Streamlit app 的自然延伸 |
| **系統健康** | 各元件延遲、資料新鮮度、LLM 成本 | 燈號 + 趨勢 |
| **回放器** | 輸入 decision_id 看完整決策鏈 | 稽核與建立信任的核心工具 |

介面上的每個數字都要能點進去看來源。**不可解釋的數字＝不會被使用的數字。**

### 交易員的否決權與回饋迴路

每張訊號卡有三個按鈕：**採用 / 忽略 / 否決（附理由）**。
否決理由是結構化選項（資料錯誤 / 我有更新資訊 / 風險太高 / 與我的部位衝突 /
時機不對），這些回饋直接進 Post-mortem Agent 的訓練資料。

**這是把「人的判斷」變成系統資產的唯一機制**，也是「不靠人一直干預交易」
與「完全排除人」之間的正確平衡點：人不做例行決策，但人的否決會教育系統。

## 5. 工具與情報來源清單

### 必要
| 類別 | 選項 | 備註 |
| --- | --- | --- |
| 行情 | 券商 API、Polygon、Databento、TEJ（台股） | 需確認再散布授權 |
| 台股資金流 | 公開資訊觀測站、TWSE/TPEX open API | 現有 `fund_flow.py` 已接 |
| 美股基本面 | SEC EDGAR（免費）、FMP、Sharadar | EDGAR 有 point-in-time 優勢 |
| 新聞 | 交易所公告、RSS、財經媒體 API | 公告類最可靠、最少雜訊 |
| 總經 | FRED、各國央行、政府統計 | 多數免費 |
| 經濟日曆 | 財報日、數據發布日 | 用於事件驅動與風險迴避 |

### 加分
- 選擇權鏈（隱含波動率偏斜、未平倉分佈）— 市場實際下注，比嘴砲可靠
- ETF 申贖與成分股變動
- 供應鏈關聯圖（建立標的間的傳導路徑）
- 衛星／貨運／招聘等另類資料（成本高，先不做）

### 明確不建議
- 未經授權爬取的社群資料（法律風險）
- 付費「訊號服務」（你無法驗證它，等於引入一個黑箱）
- 任何無法取得歷史資料的來源（無法回測＝無法驗證＝不能用）

## 6. 衡量系統本身的指標

| 指標 | 目標 | 意義 |
| --- | --- | --- |
| P1 訊號採用率 | > 50% | 訊號品質與相關性 |
| 訊號後 5 日 hit rate | > 55% | 預測力 |
| 每日 P1 訊號數 | 2~5 | 沒有洗版 |
| 從事件發生到訊號發出的延遲 | < 60 秒 | 時效性 |
| 假警報率（P0/P1 誤判） | < 5% | 信任度 |
| 交易員每日省下的研究時數 | > 2 小時 | 這才是內部工具的真實 ROI |
| 資料新鮮度 SLA 達成率 | > 99% | 基礎建設健康 |
