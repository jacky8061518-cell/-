# 09 研究平台：四平面與驗證閘門

本文件說明 `src/quant_platform/` 的設計。它是整套系統的**脊椎**：
決定一個想法能不能變成可以動用資金的模型。

前八份文件描述的是「訊號怎麼產生」。這一份描述的是
「憑什麼相信那個訊號」——而後者才是真正的護城河。

## 1. 四個彼此隔離的平面

```text
┌── Data Plane ─────────────────────────────────────────┐
│ 取得、驗證、保存。point-in-time 正確性在此保證。        │
│ 不知道任何策略的存在。                                  │
└───────────────────────────────────────────────────────┘
              ↑                        ↑
┌── Research Plane ──────────┐   ┌── Control Plane ─────┐
│ 假說 → 因子 → 回測 → 驗證   │   │ 風控、registry、審計   │
│ **沒有券商憑證**            │   │ **不接受自然語言指令** │
└────────────────────────────┘   └──────────────────────┘
              ↑
┌── Trading Plane ──────────────────────────────────────┐
│ 只執行「已核准、已版本化」的模型。無法自行發明模型。     │
└───────────────────────────────────────────────────────┘
```

**允許的依賴方向**：`data ← research ← trading`，以及 `data ← control`。

這不是文件上的約定，是 `tests/test_platform_boundaries.py` 用 AST 分析
import graph 強制執行的。Research plane 只要 import 了 trading，CI 就紅燈。

理由：Research Agent 若能碰到執行路徑，四平面就只是四個資料夾。
Control plane 不得 import research 的另一個理由更微妙——
**檢查閘門的程式碼不能依賴被檢查的程式碼**，否則研究者可以透過改
validation 模組來放寬 registry 的門檻。所以 registry 收的是「驗證紀錄」
這種純資料，不是 `ValidationReport` 物件。

Control plane 還有一條機械性檢查：任何函式簽章都不得出現
`prompt`、`instruction`、`message`、`llm_response` 這類參數。
**能被說服的風控不是風控。**

## 2. Point-in-time：兩道機制

### 發布延遲（publication lag）
每個來源宣告「事件發生後多久這筆資料才真的可用」：

| 來源 | 發布延遲 | 可交易延遲 | 理由 |
| --- | --- | --- | --- |
| prices | 0 小時 | 1 個交易日 | 收盤價收盤時已知，但最快隔日才成交 |
| flows | 20 小時 | 1 個交易日 | 三大法人買賣超當晚公布 |
| fundamentals | 45 天 | 1 個交易日 | **用期末日當可見時點是典型的前視偏誤** |
| news | 1 分鐘 | 0 | 近乎即時，但首發時間 ≠ 系統看到的時間 |

`as_of` 過濾用的是 `event_time + publication_lag`，不是 `event_time`。

### 修訂而非覆寫
更正過的數字是新的一筆（revision +1），舊的永遠保留。
在過去某個 `as_of` 查詢，回傳的是**當時看到的版本**，不是今天供應商認為對的版本。

### 誠實的限制
現有台股資料庫**沒有供應商的入庫時間戳**，所以發布延遲是「可見性的模型」，
不是「可見性的量測」。這比忽略問題好，比有真實時戳的資料源差。
延遲數值集中宣告在 `TAIWAN_SOURCES`，就是為了讓人可以逐條反駁。

### 防護
`assert_no_lookahead()` 在回測迴圈內即時檢查，不是留給夜間稽核。
只在稽核才發現的洩漏，已經產生了一季的誤導性研究。

測試 `test_backtest_result_is_identical_when_future_data_is_removed`
會把面板截斷後重跑，要求每一期報酬**逐值相同**。

## 3. 成本模型：台股的真實數字

| 成分 | 數值 | 說明 |
| --- | --- | --- |
| 手續費 | 0.1425% × 折扣（預設 6 折 = 0.0855%）| 單邊，有最低 20 元門檻 |
| 證交稅 | 股票 0.3%、ETF 0.1%、當沖 0.15% | **賣出單邊** |
| 價差 | 由交易所價格級距的 tick size 推導 | 15 元股票與 1180 元股票的相對價差差很多 |
| 滑價 | 3 bps | 假設值 |
| 市場衝擊 | k·σ·√參與率 | 平方根律 |

實測來回成本：

```
    15 元 (tick 0.05)   104 bps      250 元 (tick 0.5)    91 bps
    45 元 (tick 0.05)    82 bps      640 元 (tick 1.0)    86 bps
    88 元 (tick 0.1)     82 bps     1180 元 (tick 5.0)   113 bps
```

低價股與高價股成本最高，原因不同：前者 tick 佔價格比例大，後者 tick 跳到 5 元。

**最低下單金額 23,392 元**：低於此，固定的 20 元最低手續費會超過按比例的手續費，
等於在為「部位太小」繳固定稅。

### 換手率才是成本乘數
續抱的部位不會重新買賣。每期都收全額來回成本，是讓一個真正有效的
低換手策略看起來像輸家最快的方法。實測差異：

| 因子 | 換手率 | 每期成本（錯誤算法） | 每期成本（正確） |
| --- | --- | --- | --- |
| momentum | 31% | 0.982% | 0.306% |
| low_volatility | 20% | 0.941% | 0.192% |
| mean_reversion | 76% | 0.931% | 0.710% |

這個 bug 曾讓動能因子的淨報酬從 **+0.41%/期變成 −0.27%/期**，
足以讓一個該被進一步研究的因子被直接丟掉。

### 壓力測試不動法定稅率
`stressed(3)` 只放大「估計出來的、可爭論的」成分。
把法定證交稅也乘三倍，會讓測試看起來嚴格，但測的是錯的東西。

## 4. 驗證閘門

閘門的工作是**說不**。每一項檢驗都因為某個策略曾經通過了粗糙的審查、
然後賠錢而存在。

### 硬性門檻（未通過即不得晉級）

| 檢驗 | 門檻 | 為什麼 |
| --- | --- | --- |
| 交易檔次 | ≥ 200 | 交易次數過少時統計上什麼都證明不了 |
| 獨立期數 | ≥ 60 | 期數不足無法估計 Sharpe |
| 扣成本後為正 | > 0 | 毛報酬為正但淨報酬為負的策略，是在為券商工作 |
| **Deflated Sharpe** | **> 0.95** | 針對「試了幾次才挑到這個」做修正 |
| **Sharpe 信賴區間下界** | **> 0** | bootstrap 95% 區間下界仍為正才算穩健 |
| 成本壓力 ×3 | > 0 | 成本假設是最軟的輸入 |
| 延遲一日衰減 | < 50% | 延後一天就消失的 edge，實務上抓不到 |
| 隨機化對照 | 實際 Sharpe > 打亂後的最大值 | 打亂訊號仍有績效 = 流程有洩漏 |

### 警示（可通過，但需人工複核）
跨年份穩定性 ≥ 50%、成本佔毛報酬 < 50%、最大回撤 > −25%。

### Deflated Sharpe 為什麼是硬門檻

搜尋 100 組無效策略，最好的那組期望 Sharpe 約 **0.51**——純粹來自運氣。
`expected_max_sharpe(trials, variance)` 算的就是這個數，觀察到的 Sharpe
必須先超過它才算證據。

`--trials` 參數要**誠實填寫**。填小會讓 DSR 過度樂觀，那是在騙自己。

### 隨機化對照怎麼做
把因子分數在橫斷面上隨機重排，其餘流程完全不動，跑 8 次。
若打亂後仍有正績效，代表 edge 不來自訊號而來自流程本身（通常是洩漏）。

## 5. Model lifecycle

```text
research → validated → shadow → paper → canary → production
                                                     ↓
                                                  retired
```

registry 強制三件事：

1. **不得跳級**。`research` 只能到 `validated` 或 `retired`。
2. **未通過驗證不得進入 validated**。拒絕時會列出是哪幾項硬門檻沒過。
3. **停留時間下限**：shadow 30 天、paper 60 天、canary 30 天。
   這不是官僚程序——它是唯一能看見「模型成本」與「實際成交成本」落差的方法，
   而那個落差沒有任何回測顯示得出來。

另外，**canary 與 production 需要具名的人工核准**。
系統可以自己搜尋、自己驗證、自己寫報告，但**按下動用資金那個按鈕的是人**。
這既是風控，也是多數轄區對演算法交易的監督責任要求。

所有轉換都 append 到日誌，永不原地修改。虧損之後被問的問題永遠是
「我們當時知道什麼、什麼時候知道的」。

## 6. 三個 baseline 的實測結果

台股、市值 ≥ 50 億（959 檔）、2013–2026、多空各 10% 分位、21 日持有、
扣真實成本：

| 因子 | 換手 | 毛/期 | 成本/期 | 淨/期 | 年化 | Sharpe |
| --- | --- | --- | --- | --- | --- | --- |
| momentum | 31% | +0.716% | 0.306% | **+0.410%** | +5.04% | **0.47** |
| mean_reversion | 76% | −0.305% | 0.710% | −1.015% | −11.52% | −2.11 |
| low_volatility | 20% | −0.671% | 0.192% | −0.863% | −9.88% | −0.73 |

動能是唯一扣成本後為正的。但它**沒有通過閘門**：

```
Sharpe 0.47｜95% bootstrap 區間 [-0.06, 1.08]｜Deflated Sharpe 0.000
判定：未通過硬性門檻（Deflated Sharpe；Sharpe 信賴區間下界），不得晉級
```

信賴區間跨越零，代表這個 edge 在統計上與「沒有 edge」無法區分。
成本壓力 ×3 後只剩 +0.0006/期，等於損益兩平。

**這是好結果**，因為它是真的。閘門攔下了一個看起來還行、實際上證據不足的策略。
下一步不是調參數直到通過——那叫過度配適——要改的是假說本身。

## 7. 已知限制

| 限制 | 影響 | 處理順序 |
| --- | --- | --- |
| 無成交量資料 | 參與率是假設值，市場衝擊無法量測；ADV 限制無法檢查 | 最高 |
| 無漲跌停處理 | 台股 10% 限制下，跌停股隔日往往買不到回測假設的價格 | 高 |
| 無真實 `ingested_at` | 發布延遲是模型不是量測 | 高 |
| 無最低下單金額約束 | 回測未剔除低於 23,392 元的部位 | 中 |
| 無借券成本與可借券檢查 | 空方部位的成本被低估 | 中 |
| 單一市場 | 未做跨市場驗證 | 中 |

**漲跌停那條特別重要**：mean_reversion 因子挑的正是單日超額變動最大的股票，
而那些股票有相當比例是觸及漲跌停的——回測假設能在收盤價成交，
實務上那天根本沒有賣單。這足以解釋它 −2.11 的 Sharpe 有多少是真的、
有多少是回測與現實的落差。
