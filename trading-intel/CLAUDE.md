# 專案守則

## 語言
所有註解、文件、commit message 使用繁體中文。程式碼識別字用英文。

## 不可違反
1. LLM 產生的數值不得進入訊號計算或下單路徑。LLM 只做語意任務。
2. 任何讀取歷史資料的函式必須接受 `asof: datetime` 參數並據以過濾 `ingest_time`。沒有 asof 的資料存取函式一律視為 bug。
3. 回測執行期間禁止任何網路呼叫。偵測到即讓測試失敗。
4. 系統內部時間一律 UTC，只在展示層轉換為台北時間。
5. 所有參數放 configs/，程式碼中出現魔術數字即為 bug。
6. 資料品質檢查失敗時輸出 NO_TRADE 狀態，禁止填補後繼續。

## 開發流程
- 涉及數值計算的功能，先寫測試再寫實作。
- 每個 PR 必須附帶該功能的失效案例測試，不是只有 happy path。
- 新增特徵時同步新增性質測試，例如尺度不變性、平移不變性、缺值行為。
- 修改任何影響歷史訊號的邏輯，必須跑重現性測試確認舊訊號可重放。

## 品質門檻
- mypy --strict 通過
- ruff 通過
- 測試覆蓋率 src/features、src/backtest、src/risk 三個目錄不得低於 90%
- 每次提交前跑 `make check`

## 詢問時機
遇到以下情況停下來問，不要自行決定
- 需要引入新的外部資料源
- 需要放寬上述任一條不可違反規則
- 效能最佳化會犧牲可重現性
- 風控參數的具體數值
