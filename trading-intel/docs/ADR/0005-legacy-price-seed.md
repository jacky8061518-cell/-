# ADR 0005 — 保留既有十四年已調整價作為唯讀歷史種子

- **狀態**：已採納（經核定）
- **日期**：2026-09-09
- **階段**：Phase 1

## 背景

`data/databases/tw/adjusted-prices.parquet` 有 2012-01-02 起、3560 個交易日、
2333 檔標的的價格。重抓要很久，更早的歷史 Yahoo 未必給得回來。

但它違反 SPEC 3.2 的兩點：

1. 它是**已調整價**，而非「未調整原始價 + 獨立因子表」；
2. 它經過 `.ffill()` 前值填補，停牌期間的價格是補出來的。

## 決策

保留，當作**唯讀歷史種子**，並在程式碼層明確標記其性質：

- 來源常數 `LEGACY_SOURCE = "legacy-adjusted"`；
- 由它推導的任何調整因子，來源為 `ActionSource.LEGACY`，信心值 0.8 而非 1.0；
- `ingest_time` 統一取檔案 mtime——不精確，但保守：整批視為同時送達，
  不會讓任何一筆看起來比實際更早可用。

新資料一律走新路徑（未調整原始價 + 官方除權息因子）。

## 實測發現：這份資料的存活者偏誤比預期嚴重

寫測試時實際量測，結果是：

> **2333 檔標的中，最後有值日期等於資料結尾者：2333 檔。**

也就是**沒有任何一檔曾經退出宇宙**。原因不是 ffill 掩蓋了下市，而是更根本的：
既有的 `security-master.csv` 是從 TWSE openapi 抓「現在還在市」的清單，
下市股票從來沒有被抓進來過。

這個缺陷**無法靠處理現有資料修好**——資料裡就是沒有那些公司。

因此本 ADR 追加一項決策：`ingestion/legacy.py` 提供 `diagnose_survivorship()`，
把這個缺陷量化並回報；`tests/integration/test_legacy_import.py` 斷言這個缺陷
**確實存在**。當資料被換成無偏誤版本時，那個測試會失敗——那正是我們希望被通知
的時刻。

## 後果

**可以用這份資料做的事**

- 開發與測試資料管線；
- 計算個股的時序特徵（單一標的的歷史報酬序列大致可信）；
- 作為 Phase 2 回測引擎的煙霧測試輸入。

**不可以用這份資料做的事**

- **選股回測。** 從一個全部由倖存者組成的宇宙裡選股，績效必然虛高，
  而且沒有任何徵兆。
- 任何宣稱「這是歷史上真實可投資宇宙」的分析。

**代價**

2012–2026 這段歷史的企業行動無法重新推導，回測跨越這段期間時，
調整假設是繼承來的、不是自己算的。

## 解除條件

接上交易所的上市下市公告資料源（TWSE 每日收盤行情的異動清單，或
公開資訊觀測站的終止上市公告），重建 `universe_membership` 之後，
本 ADR 的限制解除。在那之前，`diagnose_survivorship()` 的輸出應該出現在
任何用到這份資料的報告裡。
