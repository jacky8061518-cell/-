# ADR 0007 — 新增 Yahoo Finance 作為即時／近期價格資料源

- **狀態**：已採納（經使用者指示核定：「其他都按造你最建議的去改」）
- **日期**：2026-09-13
- **階段**：Phase 1／Phase 2（補件）

## 背景

執行環境的網路政策原本擋下所有金融網站（見 ADR 0006）。使用者將 Cloud
environment 的 Network access 從 Trusted 改為 Full／Custom 後，重新實測發現
**結果分三種**，不是「開了就全部都通」：

| 來源 | 結果 |
|---|---|
| `openapi.twse.com.tw`（證交所開放資料）| ❌ 仍被擋——但擋的不是我們的網路政策 |
| `www.twse.com.tw`（證交所 T86 等舊式端點）| ❌ 同樣被擋 |
| `www.tpex.org.tw`（櫃買中心）| ✅ 正常 |
| `query1.finance.yahoo.com`（Yahoo Finance）| ✅ 正常 |

診斷：對 `openapi.twse.com.tw` 的任意 API 路徑發出請求，**HTTP 狀態碼是
200**，但回應內容是 TWSE 自己的資安警示頁（「因為安全性考量，您所執行的
頁面無法呈現」）。裸網域首頁請求則正常回應。這是 TWSE 自己的 WAF 對雲端
機房 IP 段的封鎖，是路徑層級的規則，與我們的網路政策或請求內容無關，
也不是能從程式碼層繞過、或應該嘗試繞過的東西。

## 決策

新增 `ingestion/yahoo.py`，以 Yahoo Finance 的 chart API 抓取日線資料，
補上 TWSE 連不上時原本卡住的兩件事：

1. Phase 2 驗收條件 3（基準策略績效落在文獻合理範圍）——需要價格資料；
2. 未來若要重建無存活者偏誤的宇宙，Yahoo 的資料是 TWSE 官方上市下市公告
   之外的一個替代線索（但信心層級低於官方公告）。

既有 `ingestion/twse.py` 的程式碼保留不動：解析函式已用真實格式樣本
完整測試過，抓取函式在 TWSE 解除封鎖（或改用非雲端 IP 執行）後可直接
使用，不需要重寫。

## 這一次的教訓：抓到了什麼可信、不代表抓到了全部可信

寫這個模組與其測試的過程中，連續抓到兩個**不會報錯、看起來正常**的
回測引擎 bug：

1. `BuyAndHold` 策略天真地每天回傳同一組等權權重，而回測引擎當時的設計
   是每天都用當天的權益與價格重新換算一次目標股數——即使權重完全沒變，
   價格一有波動就會被迫產生交易。實測：五檔股票、兩年真實資料，
   本該只交易一次的買進持有，跑出 **2420 筆成交**。
2. 修正方式從策略層（記住參考價、用價格漂移推導權重）改到引擎層
   （只有目標權重真的改變的標的才重新換算股數），因為策略永遠無法知道
   「明天」的真正成交價，這個限制在策略層修不掉。

兩個 bug 都被 Phase 2 原本卡住、後來用真實資料補上的這個測試抓到——如果
一直用合成資料測，這兩個問題可能不會被發現，因為合成測試多半用固定或
簡單的價格序列，不會產生足夠的日常波動去觸發這個誤差。這是「用已知答案
的合成資料測試」與「用真實資料驗證」兩者互補、缺一不可的具體例子。

修正細節見 `backtest/engine.py`（`_rebalance` 的說明）與
`backtest/baselines.py`（`BuyAndHold` 的說明）。

## 後果

- `ingestion/yahoo.py` 的抓取函式需要網路，回測期間仍然被 `no_network()`
  擋下（`tests/integration/test_live_baseline_validation.py` 有測試確認）。
- Yahoo 的價格是**調整後價格**，與 SPEC 3.2「存未調整原始價」的原則一樣
  有 ADR 0005 那種取捨；本模組同時保留 `close`（未調整）與 `adjclose`
  （調整後）兩個欄位，讓下游自行選擇，而不是被迫只能用一種。
- Phase 2 驗收條件 3 現在可以用真實資料執行，但受限於 Yahoo Finance 免費
  API 的歷史深度（本次測試用 2 年），不是完整的長期回測驗證。

## 已否決的替代方案

- **想辦法繞過 TWSE 的 WAF**（換 User-Agent、加 Referer、模擬瀏覽器行為等）。
  這是對方明確設置的存取控制，繞過它不是我們該做的事，環境的網路政策
  說明文件本身也是同樣的態度（「不要重試或繞道，回報被擋的主機」）。
- **只用 TPEx，不接 Yahoo**。TPEx 只有三大法人買賣超，沒有價格資料，
  無法單獨滿足 Phase 2 驗收條件 3 的需求。
